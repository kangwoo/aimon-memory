# ADR 0008 — 아키텍처 서술은 arc42 문서 하나로 모으고, 명세는 건드리지 않는다

**상태:** accepted · 2026-09-05

## 맥락

문서가 늘면서 아키텍처 서술이 흩어졌다.

README 는 385줄이었고 여섯 가지 일을 하고 있었다 — 제품 소개, 실행 안내, 모듈 그래프, 설계 결정,
테스트·평가 관문, 미완 목록. 그중 뒤의 넷은 아키텍처 서술이지 첫 화면이 할 일이 아니다.

그리고 같은 사실이 세 곳에 있었다.

| 사실 | 있던 곳 |
|---|---|
| 융합 공식 | README · `concepts.md` · `guide.md` (+ 냉동된 명세) |
| `N + N(N−1)` fan-out 비용 | README · `concepts.md` · `guide.md` (+ ADR 0006) |
| 3티어 표 | README · `concepts.md` · `guide.md` |

새 사실이 생겼을 때 어디 적어야 하는지에 답이 없었던 것이 원인이다. 형식이 아니라 소유권 문제다.

동시에, 아키텍처 문서를 새로 만드는 것은 [ADR 0005](0005-agpl-boundary.md) 가 서 있는 자리를
건드린다. 그 결정의 주장은 **"명세는 `aimon-memory-design.md` 하나뿐"** 이고, 그것이 하나여야 클린룸
주장이 성립한다. arc42 문서는 구조적으로 명세를 닮았다 — §1 목표, §3 범위, §5 빌딩블록, §10 품질
요구사항. 완결된 아키텍처 문서가 냉동된 명세 옆에 놓이면 "어느 쪽이 규범인가"가 생긴다.

## 결정

**`docs/architecture.md` 가 아키텍처 서술의 정본이고, 절 구조는 arc42 를 따른다. 그리고 그 문서는
규범이 아니라 서술이다.**

네 가지를 함께 정한다.

**1. 서술적이지 규범적이지 않다.** `architecture.md` 는 지금 구현이 무엇인지 적을 뿐, 무엇이어야
하는지 정하지 않는다. 문서 맨 위가 그것을 명시하고, 냉동된 명세를 가리킨다. 명세는 여전히
`spec/aimon-memory-design.md` 하나이고 ADR 0005 는 그대로 선다. 둘이 어긋나면 그 자리는 ADR 이 이미
기록하고 있거나, 새 ADR 이 필요한 자리다.

**2. README 는 아키텍처 서술을 넘긴다.** 모듈 그래프, 설계 노트, 테스트·평가 관문, 미완 목록이
`architecture.md` 로 간다. README 에 남는 것은 무엇인지 · 어떻게 띄우는지 · 어디로 가는지 셋이다.
README 를 없애지는 않는다. 첫 화면은 첫 화면의 일이 있다.

**3. §7 과 §9 는 참조만 한다.** 배포는 `runbook.md` 가, 결정은 `adr/` 이 소유한다. arc42 자신의 지침도
ADR 을 인라인하지 말고 참조하라고 한다. 두 절은 아키텍처적으로 중요한 것만 적고 정본을 가리킨다.

**4. `concepts.md` · `guide.md` · `runbook.md` 는 그대로 둔다.** arc42 §8(교차 관심사)과 §12(용어)는
`concepts.md` 를 요약하고 링크한다. `guide.md` 는 애초에 arc42 의 범위가 아니다 — arc42 는 사용자
매뉴얼이 아니라고 스스로 말한다.

### 소유권 표

이 결정의 실질은 이 표다.

| 사실 | 정본 | 나머지는 |
|---|---|---|
| 목표·제약·컨텍스트·빌딩블록·품질·리스크 | `architecture.md` | 링크 |
| 도메인 개념과 메커니즘 | `concepts.md` | 요약 + 링크 |
| 호출하는 법 | `guide.md` | 링크 |
| 배포와 운영 | `runbook.md` | 요약 + 링크 |
| 결정과 그 근거 | `adr/` | 표 + 링크 |
| 라우트·스키마·스코프 | `openapi.json` (빌드가 강제) | 링크 |
| 명세 | `spec/` (냉동) | 링크 |

## 결과

**클린룸 주장이 유지된다.** 규범 문서는 여전히 하나다. `architecture.md` 가 스스로 규범이 아니라고
말하는 것이 그 값을 치른다.

**새 사실의 자리가 정해진다.** arc42 를 쓰는 이유가 완결성이 아니라 이것이다. 이름 붙은 칸 열둘이
있으면 "이건 어디 적지"에 답이 있다.

**README 가 385줄에서 절반 아래로 줄었다.** 첫 화면이 다시 첫 화면의 일만 한다.

**대가 셋.**

문서가 하나 더 늘었다. 중복을 줄이려고 시작해서 파일을 더한 것이 모순처럼 보이지만, 줄어든 것은
파일 수가 아니라 같은 사실이 서술되는 횟수다.

arc42 절 구조를 유지해야 한다. 절을 비워 두는 것은 괜찮지만 — arc42 도 그러라고 한다 — 임의로
재배열하면 이 형식을 쓴 이유가 없어진다.

그리고 `architecture.md` 를 강제하는 것이 없다. `openapi.json` 과 달리 빌드가 이 문서를 붙들지
않는다. 모듈 그래프만은 예외로 `ModuleDependencyTest` 가 실질적으로 지키지만, 그것도 문서를 검사하는
것이 아니라 코드를 검사한다. 이 문서가 썩을 수 있다는 뜻이고, 지금은 받아들인다.
